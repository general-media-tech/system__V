## خطّ التدريب («علّمها إنت» — صيد الأنماط على **كلّ** المنتجات)
```bash
# من جذر المستودع — خادم ملفّات محلّي
(python3 -m http.server 8765 --bind 127.0.0.1 &)
node tools/lens_index_build.js --max 3            # ⇐ .lens_raw/raw.f32 (بصمة خام لكلّ صورة كتالوج)
# لقطات موبايل صناعيّة لكلّ صورة (خلفيات · رفّ مزدحم · ميلان ±18° · قرب/بعد · قصّ · إضاءة · ضبابيّة) — على عمليّتين
node tools/lens_train_aug.js --per 5 --imgs 3 --seed 1 --shard 0/2 --out aug0 &
node tools/lens_train_aug.js --per 5 --imgs 3 --seed 2 --shard 1/2 --out aug1 &
# مجموعة تقييمٍ منفصلة (بذرة أخرى — لا تُستعمل في التدريب)
node tools/lens_train_aug.js --per 2 --imgs 3 --seed 99  --shard 0/2 --out held0
node tools/lens_train_aug.js --per 2 --imgs 3 --seed 100 --shard 1/2 --out held1
# دمج الشظايا ⇒ aug.f32/aug_ids.json و heldout.f32/heldout_ids.json (انظر «الخطوة التالية» ١)
python3 tools/lens_train.py                  # تقييم: قبل (PCA) / بعد (LDA) / + نموذج أوّلي — (أ) لقطة جديدة لنفس الصورة (ب) صورة أخرى لم يُتدرَّب عليها
python3 tools/lens_train.py --alpha 0.3 --write   # يكتب lens-index.json المدرَّب (الصيغة نفسها — لا تغيير في كود الجهاز)
```
- **لماذا LDA:** يتعلّم من منتجاتنا إسقاطاً يجمع لقطات المنتج الواحد رغم الظروف ويُبعد المنتجات المتشابهة — هذا «صيد الأنماط» لا حفظ حالات (RL-24 وYM-800 مجرّد اختبارات انحدار).
- **قياسات سابقة (للمقارنة):** بصمة يدويّة (ألوان/حوافّ) ٧٪ ⇒ مرفوضة · MobileNet+PCA «صورة أخرى للمنتج» أوّل ٥ = ٤٢٪ · DINOv2-small ٥٠٪ لكنّه ٢٤ م.ب + ONNX ⇒ مؤجَّل.
