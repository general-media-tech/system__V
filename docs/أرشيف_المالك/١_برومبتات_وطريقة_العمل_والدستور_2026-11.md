- إظهار مؤشر عند وجود تغييرات غير محفوظة.
- منع إغلاق صفحة تحتوي على بيانات غير محفوظة دون تنبيه.

3. النوافذ المنبثقة المستقلة Floating Windows

لا أريد أن تكون جميع الصفحات مجرد تبويبات.

أريد أيضاً إمكانية فتح بعض الأقسام كنوافذ عائمة فوق الصفحة الحالية.

مثلاً:

- فتح الجرد كنافذة عائمة.
- فتح تفاصيل منتج دون مغادرة الصفحة.
- فتح حاسبة.
- فتح تفاصيل طلب.
- فتح أداة البحث.
- فتح نافذة متابعة المخزون.

خصائص النوافذ:

- التحريك بالسحب.
- تغيير الحجم.
- التصغير.
- التكبير إلى كامل مساحة العمل.
- الإغلاق.
- التحكم بترتيب ظهور النوافذ.
- إمكانية إبقاء نافذة فوق النوافذ الأخرى.
- إمكانية استعادة النافذة إلى حجمها ومكانها السابق.

يجب أن تكون هذه النوافذ مستقلة بصرياً ووظيفياً عن الصفحة الأساسية.

4. تقسيم مساحة العمل Split View

أريد إمكانية تقسيم الشاشة إلى أكثر من مساحة عمل.

أمثلة:

- الأوردرات في الجهة اليمنى والجرد في الجهة اليسرى.
- المخزون بجانب تفاصيل الطلب.
- الفاتورة بجانب بيانات العميل.

يجب أن يدعم:

- تقسيم الشاشة إلى قسمين.
- تغيير مساحة كل قسم بالسحب.
- تبديل أماكن الأقسام.
- إغلاق أحد الأقسام.
- العودة إلى العرض الكامل.
- إمكانية وجود أكثر من تقسيم عند توفر مساحة الشاشة.

5. نظام Undo / Redo متكامل

أريد نظام تراجع وإعادة احترافي على مستوى النظام كله.

دعم الاختصارات:

- Ctrl + Z = التراجع عن آخر عملية.
- Ctrl + Y = إعادة العملية التي تم التراجع عنها.
- Ctrl + Shift + Z = إعادة العملية في الأنظمة التي تستخدم هذا الاختصار.
- Ctrl + C = نسخ.
- Ctrl + V = لصق.
- Ctrl + X = قص.
- Ctrl + A = تحديد الكل.
- Ctrl + S = حفظ.
- Ctrl + F = بحث.
- Ctrl + K = مركز الأوامر.
- Ctrl + W = إغلاق التبويب الحالي وفق ضوابط الحماية.
- Ctrl + Tab = الانتقال إلى التبويب التالي.
- Ctrl + Shift + Tab = الرجوع إلى التبويب السابق.

مهم جداً:

يجب ألا تستولي اختصارات النظام على وظائف النسخ واللصق والتحديد داخل حقول الإدخال.

سجل العمليات History

أريد سجلاً للعمليات القابلة للتراجع، بحيث يمكن معرفة:

- ما العملية التي تم تنفيذها؟
- متى تم تنفيذها؟
- ما البيانات التي تغيرت؟
- هل يمكن التراجع عنها؟
- هل يمكن إعادتها؟

يجب أن يعمل التراجع والإعادة بشكل صحيح مع العمليات المدعومة، مثل تعديل البيانات وتغيير الكميات وتحديث السجلات.

لا تنفذ تراجعاً وهمياً.

العمليات المالية أو الحساسة أو التي ترتب آثاراً خارجية يجب أن تخضع لضوابط خاصة، مثل إنشاء عملية عكسية أو طلب تأكيد وصلاحية مناسبة بدلاً من حذف أثرها التاريخي.

6. نظام تعدد المهام على الهاتف Mobile Multitasking

هذه نقطة أساسية.

لا أريد أن تكون تجربة النوافذ المتعددة متاحة للكمبيوتر فقط.

على الهاتف يجب تقديم تجربة مناسبة للشاشة الصغيرة.

اقترح نظاماً مثل:

- شريط للتبويبات المفتوحة.
- زر لعرض جميع الصفحات المفتوحة.
- بطاقات مصغرة لكل صفحة.
- التنقل السريع بين الصفحات.
- الاحتفاظ بحالة كل صفحة.
- إمكانية فتح صفحة جديدة دون إغلاق الحالية.
- دعم النوافذ السفلية Bottom Sheets.
- إمكانية عرض صفحتين بطريقة مناسبة عندما تسمح مساحة الشاشة.
- حفظ مساحة العمل عند إغلاق المتصفح وإعادة فتحه.

يجب أن تكون التجربة مريحة باللمس، وليست نسخة مصغرة من واجهة الكمبيوتر.

7. إدارة جلسات العمل Workspaces

أريد إمكانية حفظ مجموعات الصفحات المفتوحة.

مثلاً:

Workspace المبيعات:

- الأوردرات.
- الفواتير.
- العملاء.
- المخزون.

Workspace الإدارة:

- التقارير.
- المصاريف.
- الفروع.
- الموظفون.

Workspace الجرد:

- المخزون.
- الجرد.
- حركة المنتجات.

بحيث يستطيع المستخدم الانتقال بين مساحات العمل واستعادة جميع الصفحات المرتبطة بها.

ويجب أن تكون مساحات العمل قابلة للتخصيص حسب المستخدم وصلاحياته.

8. حماية البيانات واستقلالية النوافذ

يجب التأكد من:

- عدم ضياع البيانات عند التنقل.
- عدم تكرار حفظ العمليات.
- عدم تداخل بيانات نافذتين.
- عدم تنفيذ العملية مرتين.
- عدم فقدان التعديلات غير المحفوظة.
- عدم تعارض حالة الصفحات.
- الحفاظ على صلاحيات المستخدم في جميع النوافذ.
- معالجة انتهاء جلسة تسجيل الدخول.
- عدم عرض بيانات غير مصرح بها.

9. التكامل مع نظام الاختصارات

يجب ربط جميع الميزات السابقة بنظام اختصارات لوحة المفاتيح.

مثلاً:

- Ctrl + K لفتح مركز الأوامر.
- Ctrl + T لفتح تبويب جديد.
- Ctrl + W لإغلاق التبويب الحالي.
- Ctrl + Tab للتنقل بين التبويبات.
- Ctrl + Shift + Tab للرجوع.
- Ctrl + Z للتراجع.
- Ctrl + Y لإعادة العملية.
- Ctrl + Shift + P لفتح أوامر مساحة العمل إذا لم يتعارض مع اختصارات النظام.
- Alt + Tab داخل النظام للتنقل بين النوافذ الداخلية عند تخصيصه بشكل آمن.

يجب أن تكون الاختصارات قابلة للتخصيص واكتشاف التعارضات.

10. التصميم المطلوب

أريد تجربة مؤسسية احترافية:

- تصميم أبيض نظيف.
- الأحمر كلون أساسي للهوية.
- تبويبات واضحة.
- نوافذ عائمة منظمة.
- شريط أدوات بسيط.
- أيقونات موحدة.
- حركات انتقال سلسة وخفيفة.
- عدم ازدحام الشاشة.
- عدم التأثير على سرعة النظام.

لا تحول النظام إلى واجهة مليئة بالنوافذ والعناصر العشوائية.

الأولوية لسهولة الاستخدام والوضوح.

11. طريقة التنفيذ والاختبار

قبل التنفيذ:

1. افحص بنية النظام الحالية.
2. افحص طريقة التنقل وإدارة الصفحات.
3. حدد أفضل بنية تقنية لتعدد النوافذ.
4. افحص إمكانية الاحتفاظ بحالة كل صفحة.
5. حدد الاختصارات التي قد تتعارض.
6. قدم تصوراً مرئياً لطريقة العمل على الكمبيوتر والهاتف.
7. اعرض خطة التنفيذ ومخاطرها.

بعد الموافقة:

- نفذ النظام تدريجياً.
- اختبر فتح وإغلاق النوافذ.
- اختبر التنقل بين التبويبات.
- اختبر تقسيم الشاشة.
- اختبر حفظ حالة الصفحات.
- اختبر Undo وRedo.
- اختبر الاختصارات.
- اختبر الهاتف والكمبيوتر.
- تأكد من عدم تأثر الوظائف الحالية.

لا تستبدل النظام الحالي قبل التأكد من سلامة البديل.

النتيجة النهائية:

أريد أن يستطيع الموظف فتح عدة أقسام والعمل عليها بالتوازي، والانتقال بينها بحرية، مع إمكانية التراجع عن العمليات وإعادتها، وكأنه يعمل على برنامج مكتبي احترافي متكامل وليس موقع ويب تقليدياً.
