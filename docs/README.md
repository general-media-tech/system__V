## الحالة باختصار
- **النشر:** كل دفعٍ إلى الفرع `claude/tender-tesla-1x135d` يُنشَر تلقائياً على GitHub Pages. آخر نشرٍ ناجح: الكفالة (A6) + التحقق من الشحنة للمفتي + قالب فاتورة المتجر + قراءة التتبّع + أسماء الزبائن بلا إنترنت.
- **قاعدة البيانات (مشروع Supabase «Inv excel»):** شُغّلت ملفّات SQL الإضافية الآمنة (أعمدة/جداول/فهارس) وتحقّقتُ منها بالقراءة بعد التشغيل، وآخرها عمود `gmt_orders.ship_from_office`. ملفّان فيهما حذف/استبدال دوال (توحيد دوال المخزون، ودوال إنشاء/إلغاء نقطة البيع) **ينتظران موافقة المالك** لأن أداة التشغيل تطلب موافقته على أي أمر حذف.
- **قيد العمل الآن:** سجل العمليات المقروء، الجلسة الدائمة للأدمن، أزرار الرجوع، شارات «شو الجديد»، صورة/PDF الأوردر داخلياً، الحذف بصلاحية سيادية، قفل الأوردرات، نموذج اللصق، واجهة الكمبيوتر للأوردرات والكفالة، التحديد الجماعي في الجرد، هيكلة أدوات المنتجات، فرز المنتجات القديمة، أداة «ما يطلبه الزبائن».

## قاعدة الطلبات والتعديلات (من وثيقة المالك)
1. **الطلب الأحدث يعدّل فقط التفاصيل التي يذكرها** — ولا يُلغي ما قبله كلّه.
2. الطلبات القديمة تبقى في السجلّ التاريخي، وتُدمَج في «المتطلبات الحالية».
3. قبل أي تعديل: **مقارنة إلزامية** بين الطلب الجديد وما سبقه، ويُسجَّل أيّ تعارض وكيف حُسم.
4. بعد التعديل: **اختبار عدم الفقد** — أنّ ما لم يذكره الطلب الجديد ما زال يعمل.
5. لا يُدّعى أنّ SQL يعمل قبل تشغيله والتحقق منه على القاعدة الحقيقية، ولا تُختلَق نتائج اختبار.
